# H2 预注册（单点检验 GFN2 单盆地是否方法性）——**草案，未启动**

> 依计划纪律：「**任何新起点/新方法先预注册**（唯一定义 / 成本上限 / 停止条件 / **不回填旧池**）」。
> 依据用户 2026-10-26 裁决：H2 是「唯一不越冻结项又不贵的检验」；**H1/H4 须先预注册**，H2 同样在此登记。

## 1. 检验的科学问题（唯一定义）

GFN2-xTB 层观察到 DOL/EC 的全部探针**收敛到同一极小**（P4 + v2 共 24 条）。
**H2 的命题**：这个「单盆地」是**方法性的**（GFN2 对环构象/Li 配位势面偏平），还是**真实的**（冻结的
wB97X-D4 层也认为同一极小）？

**判别方式**：用**完全冻结的生产方法**（`config/production_method_freeze_v1.json` v1.3：
`wB97X-D4 / def2-TZVPD / SMD(acetonitrile) / TightSCF SlowConv`）在 **2–3 个 v2 末几何**上做
**单点（single point，无 Opt、无 AnFreq）**，比较它们在该层的相对能：
- 若相对能级**仍在 GFN2 的同一极小排序内**（即不拉开）⇒ **H2 被否证**：GFN2 结论可信；
- 若**显著拉开**（出现 GFN2 未见的分层）⇒ **H2 得到支持**：需要更高级别的搜索，而不是继续 GFN2。

**为什么用单点而非 Opt+AnFreq**：单点**不改变几何**，因此不产生新极小、不触碰「新起点/新方法」的实质，
也不改任何接受状态；它只回答「同一几何在冻结方法下的能量」。**这是本法最便宜且最保守的形态**。

## 2. 样本（唯一定义，取自已存在的产物）

**输入几何全部来自 v2 的已回收末几何**（`work/hpc_xtb_screening_v2/tasks/**/xtbopt.xyz`），逐文件带
`final_geometry_sha256`（已登记在 v2 账本）。**只取 3 个**，按下列可复核规则选定（不挑有利结果）：

| 槽 | 取值规则 | **实测锁定值**（2026-10-27 复算，末几何 sha256 见 §6） |
|---|---|---|
| S1 | EC 侧**最低** `rel_kcal` 的 v2 末几何 | `EC|LiM_2plus ring_pucker_02`（rel **−0.00025**） |
| S2 | EC 侧**最高** `rel_kcal` 的 v2 末几何 | `EC|LiM_2plus li_coordination_away_04`（rel **+0.000045**） |
| S3 | DOL 侧 `rel_kcal` **最小**（离固定父级最远） | `DOL|LiM_2plus li_coordination_away_01`（rel **−0.345486**） |

> **锁定值由机械规则从 `work/_v2_triage_out.json` 复算得到**（非人工挑选）；
> 末几何 sha256 由 `xtbopt.xyz` 现算，与 v2 账本的 `final_geometry_sha256` 应对账一致。
> 三条规则**先写死、后取值**，故不构成「挑有利结果」。

**另附一个参照**：每个样本**同时**对其**已登记极小的几何**做同法单点（`kept=true` 的 motif 几何），
用于给出「同法下的参考能量」。这样 3 个样本 × 2 = **6 次单点**，仍远低于预算。

## 3. 成本上限（按**单点基准**，不是生产腿基准）

- 单点实测基准：**中位 81 s ≈ 0.09 CH**（按 4 核；见并行核验记录）。
- **上限：6 次单点 × 0.09 CH ≈ 0.54 CH**；再留 2 倍余量 ⇒ **硬上限 1.2 CH**。
- **从筛选余量支付**（当前余 **30.12 CH**），**不从 512/256 支取，不申请增量**。
- **停止条件**：若首个单点耗时 > 5 min 或出现 SCF 不收敛 ⇒ **立即停**，只报「H2 未完成 + 实测耗时」，不续投。

## 4. 资源与执行形态（若批准）

| 项 | 值 |
|---|---|
| 引擎 | ORCA（**只在 Slurm 计算节点**跑；本机禁跑） |

| 预算门 | 按**作业**口径（1 数组 / 2 核组… **以 v2 教训为准**：数组元素 ≠ 作业），预留 = 元素数 × 核 × 墙钟；**须与「按作业」口径核对一次** |

**关键纪律（v2 血泪）**：① sbatch 必须显式 `#SBATCH --partition=hpxg`；② 路径用 `cd "${SLURM_SUBMIT_DIR}"`，
**不用 `$(dirname "$0")`**；③ 核数**三方一致**（`cores.txt` = sbatch `--ntasks`×`--cpus-per-task` = profile）；
④ `PACKAGE_SHA256SUMS` **不含自身，须补传**；⑤ 数组元素 → 任务映射**以批次清单为权威**。
