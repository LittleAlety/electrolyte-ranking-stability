## 1. 检验的科学问题（唯一定义）

GFN2-xTB 层观察到 DOL/EC 的全部探针**收敛到同一极小**（P4 + v2 共 24 条）。
**H2 的命题**：这个「单盆地」是**方法性的**（GFN2 对环构象/Li 配位势面偏平），还是**真实的**（冻结的
wB97X-D4 层也认为同一极小）？

**判别方式**：用**完全冻结的生产方法**（`config/production_method_freeze_v1.json` v1.3：
`wB97X-D4 / def2-TZVPD / SMD(acetonitrile) / TightSCF SlowConv`）在 **2–3 个 v2 末几何**上做
**单点（single point，无 Opt、无 AnFreq）**，比较它们在该层的相对能：
- 若相对能级**仍在 GFN2 的同一极小排序内**（即不拉开）⇒ **H2 被否证**：GFN2 结论可信；
- 若**显著拉开**（出现 GFN2 未见的分层）⇒ **H2 得到支持**：需要更高级别的搜索，而不是继续 GFN2。

**为什么用单点而非 Opt+AnFreq**：单点**不改变几何**，因此不产生新极小、不触碰「新起点/新方法」的实质，
也不改任何接受状态；它只回答「同一几何在冻结方法下的能量」。**这是本法最便宜且最保守的形态**。

## 3. 成本上限（按**单点基准**，且**分开写「实测估算」与「提交器预留」**）

> **口径更正（2026-10-27 自查）**：本节初版只写「硬上限 1.2 CH」，那是**实测估算**；
> 而提交器的预算是 `核 × 墙钟 × 元素数`。若按 1 h 墙钟，**6 元素 × 4 核 × 1 h = 24 CH**，
> 与我写的 1.2 CH 相差 **20 倍** —— 包一提交就会撞面额。**两者必须分开写**，否则「上限」是假的。

| 口径 | 数值 | 说明 |
|---|---|---|
| **实测估算** | 单点中位 **81 s ≈ 0.09 CH**（4 核） | 6 次 ≈ **0.54 CH** |
| **提交器预留（按墙钟）** | `4 核 × 墙钟 × 6 元素` | **墙钟必须压到能让预留 ≤ 预算** |
| **本批硬上限（预留口径）** | **≤ 2.0 CH** | 需墙钟 ≤ **5 分钟**/元素（4×0.0833×6 = 1.999） |
| 预算来源 | 筛选余量 **30.12 CH** | 不动 512/256、不申请增量 |

**因此必须钉死的执行参数**：
- `#SBATCH --time=00:05:00`（**5 分钟**，实测 81 s 的 ~4 倍余量）；
- 若某个单点 5 分钟未完成 ⇒ **Slurm 直接杀掉**，按 §3 停止条件只报「未完成 + 实测耗时」，**不续投**；
- **不**使用 1 h 墙钟——那会把预留放大到 24 CH，等于悄悄占掉 80% 的筛选余量。

**停止条件**：首个单点 > 5 min（被杀）或 SCF 不收敛 ⇒ **立即停**，只报「H2 未完成 + 实测耗时」，不续投。

## 9. 提交前五门实测（2026-10-27）与一处**新发现的真缺陷**

**五门复验（离线、提交器自身门函数求值）**：
| 门 | 实测 |
|---|---|
| 包清单/批次 | `_load_package` count=6、`batches[0].array="0-5%6"` |
| 核数一致 | `declared_task_cores=4` == profile `cores=4` |
| 预算 | `committed 0 + reserved 2.0 ≤ cap 2` ✔ |
| 墙钟 | `--time=00:05:00`（由 profile 的 1/12 h 换算） |
| 单点纪律 | `--check` 断言 job.inp 无 `Opt`/`AnFreq`/`NumGrad` |

**新发现的真缺陷（提交器，非本包）**：`budget_headroom()` 用的是 **profile 的 `wall_hours`**，
而**不读**脚本里的 `#SBATCH --time`；且提交时**会用 profile 值改写脚本墙钟**（`:424-426`）。
⇒ 我原先把「5 分钟」写在 sbatch 里**是无效的**：预留仍按 1 h 算 = **24 CH**，被 2 CH 上限拒绝（实测报错）。
**修法（已入库）**：
1. 新增专用 profile **`h2_single_point_v1`** = `{engine orca, cores 4, wall_hours 1/12, cap 2, ledger required}`
   —— 墙钟属于**资源协议**，必须写在 profile 里，不能藏在脚本；改 profile 不波及 v2/orca。
2. `wall = "%02d:00:00"` 会**把 1/12 h 截成 00:00:00**（Slurm 会立刻杀作业）⇒ 改为
   `"%02d:%02d:00"` 的分钟级换算；**回归实测**：orca 24:00:00 / v1 02:00:00 / v2 01:00:00 **三个旧 profile 输出完全不变**，
   H2 得 `00:05:00`。`test_submit_hpc_batch` 12 项全过。
**教训**：**「参数写在脚本里」不等于「参数会被采用」**——凡提交器会改写/重算的量，必须写进它读取的那一层（profile）。

## 11. 判定入口（2026-10-27 补齐）——`work/_h2_retrieve_and_judge.py`

**为什么必须先有它**：计划 item 2 的警告原话是「**避免计算成功后才发现验收器无入口**」。
H2 的通用回收器是 **xTB 导向**的（只认 `xtbopt.*`），而 H2 产出的是 **ORCA 单点输出**（`job.out`）
⇒ 若不预先补，作业跑完将**无处判定**。

**两种模式**：
- `--selftest`（**离线**，无需超算）：合成 7 类 ORCA 输出并断言分类正确；
- `--plan-fetch JOBID`：**只打印**逐元素 `sacct` / `sha256sum` 检索命令（不执行），供 runbook 使用。

**判定规则（7 类，全部离线自测通过）**：
| 情形 | 状态 | 依据 |
|---|---|---|
| 正常终止 + 有能量 + 几何未变 | **`computed`** | `FINAL SINGLE POINT ENERGY` 解析成功 |
| 无 `ORCA TERMINATED NORMALLY` | `technical_failed` | 截断/被杀 |
| 正常终止但**无能量行** | `no_energy_parsed` | 不许把「终止」当「有结果」 |
| 输出含 `GEOMETRY OPTIMIZATION CONVERGED` | `method_drift_not_single_point` | **单点不得优化**（方法漂移） |
| 输出含 `VIBRATIONAL FREQUENCIES` | `method_drift_not_single_point` | **单点不得算 Hessian** |
| 末几何哈希 ≠ 输入哈希 | `geometry_changed_in_single_point` | 单点必须**不改几何** |

**H2 最终判定**（冻结在预注册稿）：同一槽位 {v2 末几何, 已登记极小} 的 DFT 能量差
**< 0.5 kcal/mol ⇒ `h2_falsified_same_basin`**（GFN2 的「同一盆地」得到冻结方法支持）；
**≥ 0.5 ⇒ `h2_supported_split_detected`**（需更高级别搜索）。

**RED 实证**（`work/_h2_judge_red.py`）：逐条删除 guard 后必须变红——实测三条 guard
（termination / single-point drift / no-energy）各自删除后 `exit=1` ⇒ **RED PROVEN**。
**过程中发现并修掉一个真缺口**：`no_energy_parsed` 分支最初**没有任何用例覆盖**
（我引用的用例名不存在），是 RED 把它抓出来的。
