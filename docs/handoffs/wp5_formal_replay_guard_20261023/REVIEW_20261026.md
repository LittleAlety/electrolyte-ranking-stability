### 问题 3：是否只读——实跑证明（非仅读码）

**强证据（隔离副本，排除并发干扰）**：把审计器 + 其读取的 5 个数据面 + helper + 自带测试复制到一个 686 文件的独立目录，快照 `(path, size, mtime_ns)`，连跑「审计两版本 + 不带 -B 的审计 + `unittest`（作者全自测）」，再快照——**686 文件零差异**（命令 #5）。审计器对 `outputs/**`、`scripts/**`、`data/**` **无任何写操作**；作者自测全部在 `tempfile` 里造夹具，也不写生产树。

**真实仓库单轮证明**：对审计器读取的 5 个面（blind_replay / cost / ensembles / metadata / scripts\wp_production，共 206 文件）跑单轮 `knn_v1`（退出 2）前后快照——**206 文件零差异**（命令 #8）。

**两处诚实边界（不影响「只读生产树」的结论，但必须写明）**：
1. **字节码**：`audit.py:16` 设 `sys.dont_write_bytecode=True`，但实测**导入**它做测试时**不带 `-B`** 仍会写出 `audit.cpython-310.pyc` 与 `test_audit.cpython-310.pyc`（命令 #6）——即 `dont_write_bytecode` 对「被 import 的模块自身」**不生效**（该标志在模块体内才置位，太晚）。直接 `python -B …/audit.py` 作为 `__main__` 运行从不产生 pyc；README §1「始终使用 -B」是**真正的护栏**，且要求接线方遵守。
2. **stdout**：它向 stdout 打印一个 JSON（`:408`），这是输出**不是写盘**；但若接线脚本 `> report.json` 重定向，那是**接线方的写**，不是审计器的写。
3. 我最初的「全树 before/after」对比里出现的差异（`four_state_recovery_*` 若干文件、`tests/test_resolved_route_evidence.py`、`__sandbox_probe_audit.tmp`）经核**全部是并行成员会话写入 + DSH 沙箱写探针**（`__sandbox_probe_audit.tmp` 内容为 `probe\n`、mtime 落在我的 pwsh 调用窗口），**与 audit.py 无关**——这正是我改用隔离副本/定向面做只读证明的原因。

**结论（问题 3）**：**是只读**。审计器运行时对生产树零写入（隔离副本 686 文件 + 真实 206 文件双重零差异）。唯一需遵守的是 `-B`，否则作为被导入模块可能落 `__pycache__`（属其自带测试的跑法，不属生产接线路径）。

### 问题 4：能否区分三种情形（没产生 / 没接出来 / 存在但未通过）——能
