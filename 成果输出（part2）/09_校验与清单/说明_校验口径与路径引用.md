# 校验口径与路径引用说明

本文件用于解释 `09_校验与清单/` 下三类文件的口径，以及**重组后路径引用怎么读**。

## 1. `SHA256SUMS_新结构.txt` — 本目录当前的可信校验清单

- 覆盖重组后新结构的**全部 391 个文件**（不含本清单自身与 `新结构文件清单.csv`）。
- 行格式：`<sha256>  <相对本目录的路径>`，按路径字节序排序。
- 复核方式：

  ```bash
  cd "E:/Claude Code/电解液溶剂-HB/成果输出（part2）"
  sha256sum -c --quiet "09_校验与清单/SHA256SUMS_新结构.txt"    # 全部通过时无输出
  ```

- `新结构文件清单.csv` 是同一份信息的表格版：`大类,相对路径,字节数,sha256`。

## 2. `路径映射表_旧按周结构到新结构.csv` — 重组前的旧路径去哪了

- 555 行（重组前 `week28`–`week44` 下的全部文件，不含旧顶层 `README.md`）。
- 列：`原路径(相对目录根), 原周次, 新路径(相对目录根), sha256, 是否与其他周重复的同内容副本`。
- 用法：文档里若出现 `weekNN/outputs/weekXX/foo.csv` 这类旧镜像路径，用它查出该文件在 `03_` / `04_` 等新目录下的位置。
- 多行可以指向同一个新路径——那说明这些是**逐字节相同的重复副本**，重组时按内容去重只保留 1 份。

## 3. `按周历史镜像/weekNN/` — 冻结的历史记录，刻意不改写

每个 `weekNN/` 下保留重组前的三份按周元数据：

| 文件 | 含义 |
| --- | --- |
| `README.md` | 该周的交付说明（内容清单、验收项数、校验通过数、口径纪律） |
| `SHA256SUMS` | 该周镜像的逐文件 sha256，**路径针对重组前的按周结构** |
| `verification.json` | 该周的自检结果（检查项名、是否通过、细则） |

**为什么里面的路径不改写：** 这三份文件的作用是「冻结当时的状态、可被独立复核」。把它们内部的路径改成新结构，等于伪造历史记录，反而让 `verification.json` 里那些「与仓库逐字节一致」的断言失去参照。因此：

- 三份文件**内容一字未动**，sha256 与重组前完全相同；
- 其内部路径请用第 2 节的映射表翻译；
- 新结构的完整性以 `SHA256SUMS_新结构.txt` 为准。

## 4. 文档正文里的 `outputs/...` / `scripts/...` / `docs/...` 路径

**这些路径指的是代码仓库 `电解液溶剂HB-Code` 的相对路径，不是本镜像目录的路径。**

理由：全部技术报告、周报、`SUBMISSION.json`、各 `manifest.json` 与脚本，都是「保持仓库相对形状」的镜像产物，其正文里的相对路径同时是**复现指令**（例如「在仓库里跑 `scripts/build_week29_deliverables.py --check`」）。本目录重组后已不再与仓库形状一一对应，但仓库形状没有变，所以这些引用**保持原样才是正确的**——改了它们反而会让复现指令失效。

要在这份镜像里定位具体文件，请走映射表；要在仓库里复现，请按文档原文的路径执行。

## 4.1 指向**镜像自身位置**的引用已改写（2026-10-15）

上面第 4 节说的是指向**代码仓库**的路径（`outputs/`、`scripts/`、`docs/`），它们保持原样。但文档里还有另一类引用——**指向本镜像自己**的旧按周位置，例如 `成果输出（part2）/week28`。这类已按用户要求**全部改写**到新结构：

1. **按周冻结记录**：`09_校验与清单/按周历史镜像/weekNN/` 下的 `README.md`、`SHA256SUMS`、`verification.json`——它们记录的是**当时**的路径与哈希，改了等于伪造历史记录；

3. **镜像内的仓库构建脚本副本**：`07_代码与测试/scripts/` 下的 `build_*_deliverables.py`——它们是仓库源码的副本，改了会与仓库产生差异，且这些脚本本身就是按周生成旧结构的源头。

重组前，`week44/`（以及 `week36/`）是仓库的**逐字节镜像**，可用 `build_*_deliverables.py --check` 逐文件复核「与仓库一致」。重组为按成果种类分组后：

- 该镜像一致性断言**不再适用于本目录**（路径形状变了）；
- 内容的**逐字节保真**仍然成立，并由 `SHA256SUMS_新结构.txt` 独立担保；
- 若需要「与仓库逐字节一致」的镜像，请在 `电解液溶剂HB-Code` 里重跑对应的 `build_*_deliverables.py`。
