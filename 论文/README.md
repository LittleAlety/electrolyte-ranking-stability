## 为什么 v6/v7 没有和 v8 一起归档

按「**只有零引用才能移动**」的判据`git grep -l -F "论文/<文件名>"` 于代码仓库统计：

| 对象 | 引用数 | 结论 |
| --- | --- | --- |
| `…_v8_20261105.docx/.pdf` | **0** | 已移入 `archive/` |
| `…_v9_20261105.docx/.pdf` | **0** | 当前版本，留原位 |
| `figures/v8_*`、`figures/v9_*` | **0** | 已移入 `figures/` |
| `…_v7_*.docx/.pdf` | **6** | **原位不动**（引用分布在交接件与冻结交付镜像里，改写等于改历史记录） |
| `…_v6_*.docx/.pdf` | **2** | **原位不动**（同上） |
| `_backup_build_paper_docx_v6.py` | **7** | 原位不动 |
| `_dossier/` | **4** | 原位不动 |
| `build_paper_docx.py` | **55** | 原位不动 |

⇒ 结论：**"当前 / 已被取代"是靠本索引区分的，不是靠把旧版本都塞进 archive**。
等那些引用（多在冻结交付镜像与交接件）按流程退场后，v6/v7 再一起归档。
